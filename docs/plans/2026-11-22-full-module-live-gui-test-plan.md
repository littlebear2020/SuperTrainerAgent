## 一、背景与目标

2026-11-22 上午已完成近一周（11-15~11-22）增量的冒烟级 GUI 测试（见 `docs/2026-11-22-live-gui-test-report.md`）：个人用量页与模型模式阶梯两大新功能通过，发现部署配置漂移 F1，付费生成链路未触发。用户判定**不够细致**，要求对**每个功能模块**做全面细化测试，明确批准付费。

目标与口径：

1. **全模块**：以用户可触达的 UI 模块为清单（覆盖矩阵见 §二），每模块逐功能点执行，不跳项（blocked 需标注原因）。
2. **真实链路**：六类付费生成（图片动效/AI 视频/课程海报/语音播客/PPT/文字动效）+ 知识卡片，每类 ≥1 次端到端真实出片，产物落盘并做可解码抽查。
3. **双轨**：仓库现有 live E2E Playwright 套件（L1/L2/L3）跑自动化轨 + Agent GUI 黑盒轨，两者交叉印证。
4. **回归锚定**：对 11-16 bug 清单（`docs/2026-11-16-live-e2e-bug-handoff.md`）高优项做定向回归（Batch I），只记录「仍存在/已修复」状态，不修码。

## 三、全局测试约定

- **证据规范**：每测试点 = 操作前/后截图（目检）+ DOM 快照断言双通道；截图存 `temp/worktree-archive-20261122/home-plan/temp/full-module-e2e-20261122/`（gitignored），命名 `<批次><编号>_<动作>.png`。运行时不支持 console 日志采集，以页面可见错误表现为证据并在报告注明。
- **判定标准**：pass / fail（含复现步骤）/ blocked（依赖缺失）/ unsupported（运行时不支持的操作，如文件选择器）。
- **发现分级**：沿用 11-16 口径 P0~P4 + 置信度（代码确定/实测坐实/疑似）。
- **成本护栏**：付费失败**不自动重试**；同类型付费任务**同时在跑至多 1 个**；不故意制造付费失败；软上限 ¥100——执行中通过用量页监控累计，逼近上限先暂停请示。
- **数据卫生**：所有自建测试资源（线程/文档/任务/渠道）标题或内容带 `[e2e]` 前缀便于事后清理；只删除自己创建的数据；管理台渠道真实凭据**只读**；**不改任何账号密码**（会吊销会话且影响用户本人）。
- **会话卫生**：双 tab 策略——长任务 tab 挂机跑 + 另一 tab 继续其他批次；每批次开始前 `tabs.list()` 确认目标；执行前巡检无在途后台任务。
- **勾选制**：执行即勾选；跨会话恢复进度第一动作 = 读勾选状态。
