# Agent 新会话引导页重构设计

> **状态**：待用户评审。
> **TL;DR**：为 course-video、ppt-master、creative-studio、co-writer 的 `chats/new` 建立共享的任务型引导页，以真实案例预填提示词取代原始 Skill 名；已有对话与提交链路不变，只对 Creative Studio / Co-writer 做最小技能归属调整。

## 1. 背景与问题

当前 Agent 新会话页由通用 Bot 图标、Agent 原始 `name/description`、通用输入框和 Skill 按钮组成。主要问题不是单纯样式，而是信息架构没有围绕用户任务组织：

- 原始名称和技术描述不能告诉用户应该先提供什么。
- `/skill ...` 预填机制虽然存在，但技术名称本身没有引导价值。
- 四个 Agent 共享同样的空泛结构，缺少可理解的案例和下一步预期。
- 页面在桌面端空旷，在移动端也缺少明确的内容优先级。

## 2. 目标与非目标

### 目标

1. 用户进入四个目标 Agent 的新会话页后，可以立即理解“能做什么、该提供什么、点击案例后会发生什么”。
2. 案例点击后预填真实、可执行的提示词，聚焦输入框，但不自动发送。
3. 原始 Skill 名不再承担用户引导职责。
4. 既有对话、消息流、发送/停止、模型选择、导出、Tokens 和历史路由保持兼容。
5. 页面延续首页现有的淡紫、白底、细边框、柔和阴影与响应式布局。

### 非目标

- 不重写消息流、Agent 执行器、工具权限或提示词运行时。
- 不新增后端 API、数据库字段或付费生成调用。
- 不把 docx/pdf/xlsx/data-analysis 直接转移给只有 Web 工具且约束为 Markdown 输出的 Co-writer。
- 不删除 Creative Studio 的视频能力；本批只从其新会话引导中移除视频/研究写作入口。
- 不修改其他 Agent 的新会话内容，除非共享组件必须提供安全缺省行为。

## 3. 方案选择

### 方案 A：仅调整样式

保留原始描述和 Skill 按钮，只改颜色、间距和卡片边框。成本最低，但无法解决任务引导和技能归属不一致，不采用。

### 方案 B：共享任务型引导页 + 专属内容 + 最小技能归属调整（采用）

新增共享前端内容配置和展示组件，四个 Agent 使用各自的内容；点击案例复用现有 prompt controller 预填。Creative Studio / Co-writer 的配置与 SOUL 只做明确归属所需的调整。

### 方案 C：重做 Agent 工作流

把页面、执行流程、工具调用和产物管理一起重构。后端风险与验收成本远超当前目标，不采用。

## 4. 页面设计

仅 `chats/new` 的新会话状态显示新引导页。已有会话不得再次显示。

页面结构：

1. **任务型 Hero**：专属图标、用户可读标题、一句话价值说明。
2. **案例卡片区**：每个 Agent 3–4 张真实任务卡；每张包含名称、简短说明和预填提示词。
3. **现有 InputBox**：保持原提交、停止、上传、模型和上下文能力。
4. **上手 Tips**：说明需要准备的内容及下一步，不暴露内部 Skill 名或实现细节。

桌面采用紧凑居中容器与多列卡片，移动端单列；页面不得依赖隐藏旧 DOM 来维持旧测试。

## 5. Agent 专属内容

| Agent | 主标题 | 案例方向 | 上手提示重点 |
|---|---|---|---|
| course-video | 把知识讲成一堂视频课 | 知识科普、产品教学、原理动画、已有讲稿转视频 | 主题/受众/时长；说明会经历讲稿确认与 Remotion 渲染 |
| ppt-master | 从资料到可编辑的 PPT | 从零生成、改造现有 PPT、美化排版、品牌模板 | 支持既有源文档；强调原生可编辑 PPTX |
| creative-studio | 让知识成为好看的图片 | 知识卡片、课程海报、信息图、系列视觉卡片 | 主题、核心信息、受众、尺寸与风格 |
| co-writer | 把想法写成好内容 | 公众号文章、商业案例、视频脚本、播客文稿 | 选择内容类型；按既有 SOUL 使用大纲/全文阶段 |

Co-writer 的预填提示词必须携带现有 `[类型: …]` 与 `[从零创作]` 语义标记，确保点击案例后的请求与当前 SOUL 匹配。标记进入输入框是可接受的，因为它们是当前真实路由契约；不在案例按钮上暴露内部 Skill 名。

Course-video 不在界面展示 auto-video-flow；现有 SOUL 已指定 Remotion 直写，无需为其修改配置。

## 6. 提示词交互与状态边界

- 复用 `usePromptInputController().textInput.setInput`，不新建第二套输入状态。
- 点击案例时：写入该案例完整提示词、聚焦输入框；如已有文本则按当前策略追加，避免静默覆盖用户输入。
- 点击不自动提交，不创建线程，不调用付费生成。
- 已有会话、普通历史页面与非目标 Agent 不显示新的专属案例。
- Agent 加载中、加载失败和未知 Agent 必须提供诚实且可恢复的状态，不渲染假案例。
- 预填逻辑继续兼容既有 `?msg=` / sessionStorage handoff，不重复消费或覆盖。

## 7. Creative Studio / Co-writer 技能归属

目标是把“写作引导”和“实际能力”对齐，而不是为了页面效果误删功能。

- Creative Studio 的研究写作请求明确引导至 Co-writer。
- 仅将支持文章/案例写作的 `deep-research`、`consulting-analysis` 纳入 Co-writer 的技能配置，并相应更新 SOUL 中的使用边界。
- Creative Studio 的视觉技能保留；其研究写作引导移除，视频能力保留但不在新页面宣传。
- 不向 Co-writer 转移需要文件写入、Bash 或表格产物的技能；不扩大其 `tool_groups`。
- 种子配置与 SOUL 的修改属于能力归属调整，不改后端运行代码、API 或数据库。

## 8. 组件与数据设计（计划阶段待核对）

优先考虑：

- 一个前端静态内容 SoT：Agent ID → 标题、说明、图标、案例、Tips。
- 一个共享新会话引导组件，只负责展示与发出 `onSelect(prompt)`。
- 在现有 AgentChatPage / InputBox 边界接入，不重写 ChatProviders 或消息流。
- 对四个目标 Agent 停止渲染原始 Skill 按钮；其他 Agent 保留当前行为。
- 保留 `AgentWelcome` 原导出兼容旧导入；实际新页面是否复用由实现计划确定。

## 9. 验收标准

### 行为级

1. 四个 `chats/new` 路由均显示正确的专属标题、案例和 Tips，无原始 Skill 名或通用 Bot 占位。
2. 每张案例实际点击后，输入框获得该案例的正确提示词，聚焦且不自动提交。
3. 已有对话不显示新引导页；历史消息、发送、停止和模型选择不受影响。
4. `?msg=` 与长文本 handoff 不被案例状态覆盖。
5. Creative Studio 新页面不出现研究写作/视频案例；Co-writer 案例与真实 SOUL 类型匹配。
6. Creative Studio 旧别名和四个 Agent 的历史线程继续可用。
7. 桌面与 390px 移动端无横向溢出，键盘可操作，无 JavaScript 页面错误。
8. 不触发真实付费生成。

### 实现级与回归

- 静态内容配置覆盖四个 ID、案例完整性与 prompt 非空校验。
- DOM 测试覆盖预填、追加、聚焦、已有会话不显示及加载/错误状态。
- Playwright 覆盖四个新会话路由、实际点击和历史路由回归。
- 种子配置解析与 Creative Studio / Co-writer 技能归属测试通过。
- `pnpm check`、`pnpm test`、`pnpm test:e2e`、`pnpm perf:check`、根 `make check`、文档检查全部通过。

## 10. 执行前置与范围控制

当前工作区另有创建框优化批次的未提交修改，且最近一轮 E2E 存在失败。新批次实施前必须先完成或明确隔离该批次；不得把两批代码混入同一提交。

正式计划将记录基准 commit、逐项 TDD 任务、allow/ban 路径、行为级验收和回滚方式。部署不属于本设计评审。
