## Video Gen Module (`app/gateway/video_gen/`)

Unified storyboard-based video generation pipeline. Visual source types: `ai_image`, `ai_video` (Worker handoff) + `vimax` (engine layer). `remotion` renders via chat direct-write now (2026-07-15 split) — NOT a backend `/api/video/create` path.

**Architecture**: All video types share `script → storyboard → TTS → subtitle → visual_source → compose` orchestration backbone; only the visual source differs. **Engines** (`engines/`): `EngineRegistry` routes `video_type → engine` — only `vimax` is engine-routable now (`VimaxEngine`); the `remotion` engine case + `RemotionEngine`/`RemotionAgentRunner`/`agent_prompt` nested-agent chain were removed (2026-07-15 split — it re-launched course-video into itself, SOUL "don't write code" vs prompt "write code" self-contradiction → early termination, no mp4). **Agents**: `course-video` (Remotion direct-write, `auto-video-flow` skill) + `vimax-video` (ViMax backend engine; 2026-07-21 对话流收敛：蓝图确认门走 ask_clarification，提交渲染即结束本轮、不监控进度) are seeded in `backend/seed/agents/` (`SEED_VERSION` `2026-09-23`) → auto-deploy to runtime `.deer-flow/agents/` on startup → `/workspace/agents` (`category: public`). Since 2026-09-09 (创意工作合并) the seed set carries **6** public agents — card-poster/case-article/design-specialist/knowledge-extraction/video-clip 五壳合并为 `creative-studio`（web + 沙箱三件套，19 技能白名单，SOUL 按产出物模式路由）；**no seed agent ships `tool_groups: null`** (null = mount every config tool — guarded by `test_seed_agents.py`)。注意 seed 原则只增不删（显式例外：course-ppt 已于 2026-09-11 退役删除，由 ppt-master 承接）——退役壳的运行时目录须手动清理。Reseed preserves the runtime-accumulated `memory.json` (agent global memory) across version bumps.

**ai_video 时长策略 (2026-08-03)**: `frame.duration` 由 TTS 实测决定（音频是时间轴唯一真相，`audio_flow.reconcile_durations_with_audio` 在出 worker payload 前重新断言）。下发给 provider 的时长经 `duration_policy.align_to_provider_grid` **向上取整**到 provider 栅格（Ark: 整数秒 [4,15]，由 `SeedanceArkVideoProvider.min_video_duration`/`integer_seconds_only` 声明）——长了 worker `-t` 截断无损，短了才要 `tpad` 定格。生成后 gateway ffprobe 实测写入 `frame.actual_visual_duration`（**不改 duration**）；缺口 > 0.5s 记 `KIND_VISUAL_SHORTFALL` 降级，任务详情可见。提示词里写「视频时长9秒」无效——duration 是独立 API 参数，与 prompt 文本无关。

**镜头语言 (2026-08-03)**: `StoryboardFrame.shot_size`/`camera_move` 由 LLM 按枚举产出，`compose_video_prompt` 拼成中文术语下发；`smooth_camera_continuity` 在两条规划路径的汇总点消除相邻镜重复/相反运镜（块间并发调 LLM，无法在生成时衔接）。旁白字数带按叙事位置缩放（`script.word_bounds_for_position`，开场/结尾短、主体长），逐镜区间写进提示词——旁白是一次 LLM 调用产出全部镜。

**⚠️ Provider 能力属性必须穿透包裹链（2026-08-03 BUG-B 教训）**: 生产 provider **一律**经 `ThrottledAIVideoProvider`（+ 可选 `FallbackAIVideoProvider`）包裹后才交给 visual source，而**两个包裹类都没有 `__getattr__` 兜底**——只透传显式声明的 property。给 provider 类新增任何能力属性时，**必须同时**：

1. 在 `providers/throttle.py` 的 `ThrottledAIVideoProvider` 补透传 property（读 `self._inner`）；
2. 在 `providers/registry.py` 的 `FallbackAIVideoProvider` 补透传 property（读 `self._primary`，能力以 primary 为准）；
3. 若该能力进了 `providers/capabilities.py` 的静态表，确认表值与链上实际一致（否则前端校验与实际下发分叉）。

**测试必须用真实包裹链，不能用裸 mock**：`FallbackAIVideoProvider(Throttled(ark), Throttled(qihu))`。BUG-B 的教训：Task 3 只在 `SeedanceArkVideoProvider` 类上声明了 `min_video_duration`/`integer_seconds_only`，漏了两处透传 → `ai_video.fill()` 的 `getattr(provider, "min_video_duration", 0.0)` 恒取兜底值 → **整个时长栅格对齐在生产上从未生效**，而 5 个单测全绿（fixture 用 `MagicMock(min_video_duration=4.0)` 直接声明属性，绕过包裹层，测的是生产里不存在的配置）。守护测试见 `tests/test_provider_capability_passthrough.py`（含参数化断言「每个能力属性在两个包裹类上都 `hasattr`」防漂移）。改这类代码后**务必做变异验证**：撤回修复看测试是否真红。

**⚠️ 同一 provider 类的不同模型可能要求不同请求体**: `QihuVideoProvider` 同时服务 Hailuo 2.3 与 MiniMax-H3，但 **H3 强制要求扁平 `extra_body.resolution`（仅 `768P`/`2K`，`1080P` 会 400）+ `extra_body.ratio`（`16:9`/`4:3`/`1:1`/`3:4`/`9:16`/`21:9`）**，缺任一即 400；Hailuo 两者都不需要。故 `_submit` 的 `extra_body` **按模型门控**（`_is_h3_model`）而非无条件添加。主备口径已更新（2026-08-21 E3 对调）：现行 config 默认 `ai_video_provider = "seedance"`（360 主力，config.py），seedance-ark 为降级兜底（registry.py）；另注意 Hailuo 2.3 已下架。`ratio` 需兜底：`_size_to_ratio` 对非常规尺寸返回 `"adaptive"`，不在 H3 可用值内。`happyhorse`/`seedance` 子类各自 override `_submit`（前者用 `extra_body.input/parameters` 嵌套结构），不受基类此改动影响。

**AI image providers**: `ai_image_provider` config selects the image backend. `seedream` (ByteDance Ark doubao-seedream-5-0-pro-260628, 字节默认首选; text-only; 5xx/429/timeout → qihu fallback via `FallbackAIImageProvider` per requirement #4) uses `ark_api_key`/`ark_base_url`. `qihu` (360-Gemini, text-only) and `gpt-image-2` (text + reference-image editing via `/v1/images/edits`) run on the 360 gateway sharing `qihu_api_key`/`qihu_base_url`. Also on the 360 gateway (2026-09-23): `gpt-image-2.5-flare`/`gpt-image-2.5-sunburst` reuse `GptImage2Provider` with a **required** `quality` field (low/high; missing → 400) — text-to-image only, NOT in `I2I_CAPABLE_IMAGE_PROVIDERS` (2.5 `/v1/images/edits` rejects every field variant per spike; see plan 2026-09-23 appendix). `AIVisualImageProvider.generate_image` accepts an optional `reference_image_paths: list[str] | None` (absorbed via `**kwargs`); the general providers (qihu/seedream) are text-only and IGNORE it — ViMax's character-consistency reference editing uses its own bridge generator (`NanoBananaGeneratorForViMax`, §4.2 → `SeedreamGeneratorForViMax`), NOT `GptImage2Provider`.

**Task Type Routing**:
- `ai_image`, `ai_video` → storyboard pipeline → Worker handoff (ffmpeg compose)
- `vimax` → storyboard pipeline → engine layer (`VimaxEngine`: 逐镜生图 + i2v, character consistency)
- `remotion` → chat direct-write (course-video agent + `auto-video-flow` skill writes Remotion code + renders in sandbox). NOT routed via `/api/video/create` (422) — the backend remotion engine is removed.

**Remotion (chat direct-write, 2026-07-15 split)**: remotion no longer flows through `/api/video/create` (the backend `RemotionEngine`/`RemotionAgentRunner` nested-agent chain is removed). The video-gen Remotion button composes a prompt + jumps to the course-video chat agent, which uses the `auto-video-flow` skill to write Remotion code + `npx remotion render` in the sandbox directly. The legacy `pipelines/remotion_*.py` (`run`/`template`/`props`) are retained as dead code (unreachable under `engine_arch: multi_engine`); skill templates live at `skills/public/auto-video-flow/`.
